# デイリーバトル（2026-11-03更新）

## UI（2026-11-03更新）

街の起動アイコン・投票画面・再生画面は赤/えんじ系。専用画面は全画面で、通常時の閉じるボタンは右上。タイトル「デイリーバトル」は起動画面と同じMonomaniac Oneで中央揃え。開催日時は表示しない。カウントダウンはui-monospace/メンロ等の等幅フォントで表示する。8文字分の幅を確保し、数字・コロンの文字幅と全体の位置を固定する。

投票候補は「左💪／左／🌀／右／右💪」、賞金の数字はボタンに表示しない。確認ポップアップは最初から場所を確保し、表示・候補切替で投票ボタンを動かさない。確認文は「名前が圧勝すると300モジGET」「名前が勝利すると100モジGET」「引き分けると300モジGET」。賞金・抽選・保存・前回分の精算必須条件は維持する。的中後の受領専用画面は従来どおり受領するまで次へ進めない。

## 最新仕様

日本時間の18:30にその対戦を決着し、同じトランザクションで次回（翌日18:30決着分）の専用NPC2体を作って受付を開始する。対戦IDの日付は決着日。既存hourlyBattleの毎分トリガーを使うため、公開はその時刻以降の最初の実行となる。投票はFirestoreサーバー時刻で「前日18:30以上・決着日18:30未満」のみ。0:30の処理はない。GAS遅延時は「結果を確認中」、次回未作成時は「準備中」。未決着だった最後の対戦は復旧後に先に決着し、停止中の未作成の日をまとめて作らない。

通常のemojins/battles/legends/meta/gameのデータ・成績は変更しない。HPは抽選せず8固定。通常NPCと同じ基本スキルの重みで5枠を抽選し、6枠目はattack1。特殊スキルなし。名前は通常NPC同様のカナ3文字＋ン。通常エンジンの最大10ターン方式を使い、保存済みイベントだけを再生する。

1対戦・本人UIDごとに無料で1票、変更・取消不可。左から「左💪 圧勝300」「左 勝利100」「🌀 引き分け300」「右 勝利100」「右💪 圧勝300」。投票ボタン自体には賞金を表示せず、確認ポップアップで表示する。通常勝利2ボタンを広めにする。圧勝は相手HP0、通常勝利は10ターン後の残りHP差。相打ち・同HPは引き分け。

通常はスキルの左3枠だけ公開し、右3枠は?。投票候補のポップアップは別の投票ボタンへ切り替え可能で、内部の「投票」で初めて確定。確定後は全候補無効、選んでいない4つをグレーにする。別端末でも同じ投票結果を返す。

再生時は左3枠公開・右3枠?の状態から右3枠を順に派手に公開。再生速度は通常バトルと共通の端末保存値（1×/2×/4×）を使う。右上の速度ボタンで変更・保存し、その速度を以後の通常/デイリーバトルにも共用する。スキップは表示せず無効にする。☆・💀は表示しない。当選者は再生終了後の「賞金を受け取る」を押して初めてウォレットへ加算。自然回復・3,000超の残高維持・不変receiptとトランザクションによる二重受領防止を使う。

## 開催前の命名（100モジ・各個体1回）

開催前の2体の名前の横に小さい✏️を表示し、名前入力ウィンドウを開く。タイトルは「100モジでメイメイする」とし、下部の小さい説明文は置かない。変更ボタンで確定する。空白だけ・現在と同じ名前・8文字超は不可。NFCで正規化し、Unicodeコードポイント数で1〜8文字とする。通常のメインゲームの命名処理は変更しない。

各対戦日・左右それぞれ1回、全ユーザー共通の先着。投票前後を問わず、対象の対戦が受付中で開催時刻前の場合だけ変更できる。変更済み/終了済みの個体には✏️を出さない。他ユーザーの変更は小さい専用コレクションの購読で同期する。入力中にほかの人が先に確定した場合は課金せず、既に決まった名前を表示する。

`dailyBattleNames/{day}/fighters/{0|1}` に名前・命名者UID・100モジのコスト・操作ID・サーバー日時を不変保存する。同じトランザクションで本人のwalletから自然回復計算後の100モジを消費し、`wallets/{uid}/operations/daily-rename-{day}-{side}` に不変receiptを残す。ルールは名前の長さ/受付時間/未命名/本人の財布の厳密な100モジ減算/他フィールド維持/receiptを照合し、単独書き込みや無料変更、再命名を拒否する。再送時は元のreceiptを返して再課金しない。

公開battleドキュメントや秘密のスキルはクライアントから更新させない。受付中の表示は専用の名前記録を重ねる。決着時にGASの同一トランザクションで名前記録を読み、その名前で公開結果とログを作る。乱数seed・スキル・HP・勝敗・配当は変えない。終了済みの結果は再作成せず、過去ログやメインゲームの個体名には適用しない。

今回の適用は **DailyBattleScheduler.gs全文の差し替え → firestore.rules全文の公開 → フロント公開** の順。Code.gs、Engine.gs、DailyBattleEngine.gs、Migration.gs、Announcements.gs、appsscript.json、毎分トリガーの変更は不要。GAS直接連携はユーザーの指示で中止しており、GASとルールはユーザーが反映する。フロントはその完了報告後に公開する。既存データの移行やサンプルの命名は行わない。

## 開いたときの進行（未処理は最大1件）

DBの本人の最新投票を1件だけ読む。最新の実施済み対戦ではなく「本人が最後に投票した対戦」が未処理なら必ず優先する。数日不在でも飛ばさない。まだ決着前ならその投票済み対戦のカウントダウンを表示する。決着済みなら端末に保存された速度で、スキップなしで自動再生する。

的中時は再生後の賞金受け取り画面を表示する。この段階は閉じる/次へ/別の投票の経路を作らず、「賞金を受け取る」の保存成功後に受付中の投票画面へ自動で移る。通信エラーでは受領ボタンから再試行し、未処理のまま次へ進めない。不的中時は再生完了をDBへ保存してから自動で次へ移る。保存失敗時は専用の再試行画面から完了させる。

投票文書の未処理/処理済みはDBルールで管理する。的中時の処理済み更新はwallet・不変receiptと同一トランザクションで行う。新しい投票で文書を上書きできるのは前回処理済みかつ新しい対戦日の場合だけ。同じ対戦への再投票・未受領を飛ばす書き込みも拒否する。

履歴一覧・履歴ボタン・赤丸バッジ・端末の再生済み保存は削除する。再読み込みや別端末でもDBの未処理1件へ戻る。ブラウザーを閉じた場合などの再生途中状態は保存せず、再度最初から再生する。過去の共通対戦記録と賞金receiptは、不在ユーザーの結果確認と再送の二重受領防止に必要なため残す。

## 保存場所・権限

- `dailyBattleSecrets/YYYY-MM-DD`：GASのみ。全6枠・seed。クライアントのread/writeを拒否。
- `dailyBattles/YYYY-MM-DD`：認証済みread、GASのみwrite。決着前は名前・絵文字・HP・左3枠だけ。決着後だけlog/outcomeを追加。
- `meta/dailyBattle`：GASのみwrite。通常のmeta/gameを使わない。
- `dailyBattlePlayers/{uid}`：本人のみread/writeする最新投票1件。day/choice/votedAt/settled/settledAt/uid。投票先は0〜4。初回は受付中だけcreate、前回処理済みなら次回投票で上書き。未処理→処理済みは公開済み結果と必要な賞金receiptで照合。votedAt/settledAtはserverTimestamp。削除・投票先変更・未処理のままの次回投票は拒否。
- `wallets/{uid}/operations/daily-battle-YYYY-MM-DD`：不変の賞金receipt。的中済みの最新投票・公開結果・賞金額・同時ウォレット更新のrevision/残高増分/recentOperationsと、最新投票の処理済みへの同時更新をルールで照合。通常のwallet/スロット/くじの保存経路は維持。

同時受領では片方の古いwallet revisionをルールが先に拒否する場合がある。その場合でも、すでに確定済みの同じ日付のreceiptと最新財布が取得できたときだけ成功扱いで同じ記録を返す。receiptがなければ権限エラーを握りつぶさない。
