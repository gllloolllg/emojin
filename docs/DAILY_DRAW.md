# きょうのモジくじ（2026-10-27）

作業ブランチ：`feat/daily-moji-draw`。日付・表示・抽選はフロントで行い、特典精算は既存のFirestoreウォレットトランザクションを使う。継続許可に従い検証後に本番公開する。GAS・Firestoreルール・既存データの移行は不要。

## 特典

`window.DailyMojiDraw.CONFIG`を正本にする。通常特典を独立に2回抽選する。

|通常特典1枠|確率|
|---|---:|
|孵化ポイント1|30%|
|30〜150モジの整数（各値均等）|70%|

この2枠に400〜600モジの整数（各値均等）のレア特典1枠を加え、Fisher–Yatesで3か所へ均等に配置する。通常2枠が同じ種類になる場合もある。選択前に全結果を一度だけ作り、演出・再試行中に再抽選しない。モジは3,000で切り捨てず、孵化は上限10。満タン時に孵化ポイントを選ぶと追加効果はなく、他の特典への変換もしない。

## 発生と復帰

- 日本時間（UTC+9）の午前0時で日付を切り替える。本人・日付ごとに1回受け取る。オーナーのアクセス日や毎日の判定をGASへ追加しない。
- 未再生バトルとレジェンド演出の後、初回はヒント終了後に表示する。ヒント既読保存が遅くても、その端末でヒントを終えた事実を使う。表示直前に最新の状態を確認し、その間に新しく届いた未再生バトルも先に再生する。
- 既存の生成途中・別モーダル・復帰/孵化/落とし物の演出・非表示タブを中断しない。処理後の通常画面、既存の5秒UI更新でも表示可能か確認する。同日完了済みならローカル判定だけで終了する。
- localStorageの`emojin.dailyMoji.<projectId>.<uid>`に日付・確定済み3枠・選択位置・演出段階を保存する。完了後は日付と完了フラグだけを残す。同日の途中結果は再表示し、選択後なら同じ位置で自動復帰する。
- 古いタブの応答が、別タブの完了記録や翌日分の状態を上書きしない。ローカル記録が消えても、保存済みの当日特典を再加算しない。他端末で当日分を取得済みで、この端末に再生途中の記録がなければ新しいくじは出さない。
- 前日分の未送信精算は既存の再試行キューに残り、日付が変わっても同じ操作IDで精算する。日付をまたぐ場合も、生成・選択したラウンドの日付は途中変更しない。

## 見た目と順序

1. 通常のモーダル機構を使いながら、パネルの背景・枠・影を消し、半透明の黒を全画面に敷く。「きょうのモジくじ」は既存タイトルと同じMonomaniac One。
2. 🎁が3つ、画面上から順に落ちて弾む。各箱の開始待ち時間にも先頭キーフレーム（非表示）を適用し、登場前に箱が一瞬表示されるのを防ぐ。表示完了後に選択でき、待機中も揺れる。
3. 選んだ🎁が中央で拡大し、保存結果を待つ間は開封前の振動を続ける。保存が確認できてから蓋と本体が飛び、特典を拡大表示する。
4. モジはメイン画面と同じビーカーSVGに「XXモジ」を重ね、孵化は黄色く光る球と「孵化ポイント＋1」。選択した特典だけを精算する。獲得アイコンがビーカーまたは孵化ゲージへ飛び、点灯する。満タンの孵化は追加されない旨を表示する。
5. 1回タップで3つの特典を並べて公開し、選んだものを光らせる。「ほかの特典を見る」の案内文は表示しない。この段階でも残り2枠は付与しない。もう1回タップすると通常画面へ戻る。

タイトルの光、プレゼントの落下・揺れ・開封、光線、紙吹雪、特典の出現・飛来、全結果の表示に演出を付ける。OSの「視差効果を減らす」でも再生する既存方針を維持する。ビーカーを複製する際はSVGのIDを一意にする。演出中に保存済み残高が先に見えないよう、背景のモジ数を隠す。

演出中の追加選択・連打・背面操作を防ぎ、PWA更新も既存のbusy/modalガードで延期する。途中の通信エラーは、同じ選択で「再試行」か「あとで」。再試行は別の箱へ変更せず、「あとで」の場合は同じセッションで何度も開かない。次回起動で途中状態へ戻る。装飾・飛来オブジェクトは終了時に削除する。

## 精算

`dailyDraw`操作を既存の未送信キューで処理する。Firestoreの`wallets/{uid}/operations/daily-YYYY-MM-DD`を不変のreceiptにする。receiptにはkind、version付きround、選択位置、特典、実際のモジ・孵化加算量を保存する。

トランザクションは同日のreceiptを先に読み、あれば元の結果を返す。なければ既存の自然回復を計算し、選択特典だけをwallet/hatchへ加算し、walletとreceiptを同時保存する。同時実行・再試行・返答消失でも追加精算しない。`slotRound`・生成途中draft・既存成績は維持する。保存済み結果を演出中に再取得する処理は足さず、精算が返した確定結果を使う。将来の特典変更でも保存済みversion 1の結果を別の配当へ変更しない。
