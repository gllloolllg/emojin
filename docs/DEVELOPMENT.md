## 実装の境界

`app.js` は順に `EmojinEngine`、`MojiSpinEngine`、Firebase設定と `createCloud`、`createCloud().then(...)` 内のUIから成る。戦闘結果にはイベント列があり、UIは保存済み結果を再生する。

Authentication はオーナー名を正規化・ハッシュ化して合成メールアドレスにし、パスワードもハッシュ化してメール/パスワード認証に渡す。互換性に関わるため認証方式を無断変更しない。

Firestore は `owners`、`wallets`、`emojins`、`battles`、`legends`、`meta/game` を使う。receiptは `wallets/{uid}/operations/{operationId}` に保存する（参照定義は `createCloud` 内）。`wallets` には残高・基準時刻、孵化ゲージ、生成途中のdraft、進行中slotRound、revision、recentOperationsがある。worldはmeta・owner・active一覧の購読、walletは別の購読で同期する。墓地・レジェンドは必要時に取得し、一覧キャッシュは30秒、取得上限は各200件。

localStorage の `emojin.firestore.v1.emojin-49855` にはローカル状態、未送信操作、生成途中情報等が残る。これはFirestoreの代替ではない。`flush` は操作IDを保って送信し、操作別にreceiptや既存ドキュメントを照合する。`resumeWrites`、`retry`、`bounded` と revision確認を維持する。recentOperationsは直近64件であり、スロット・報酬のreceipt照合とは役割が異なる。

## 基本ルール

| 項目 | 値 |
|---|---:|
| 初期モジ | 2,000（新規オーナーのみ。既存残高は維持） |
| 自然回復 | 1分に1モジ |
| 自然回復上限 | 3,000 |
| 生成 | 生存マイエモジン数に応じて100〜1,200モジ（下表） |
| 強制バトル | 100モジ |
| チャレンジバトル | 200モジ、孵化ゲージ+2 |
| マイエモジンバトル | 200モジ、孵化ゲージ+2 |
| 孵化ゲージ | 10段階 |
| 定期バトル | GASで1時間に1回（配備・トリガーは未確認） |

`accrueMoji` は保存残高と経過分から算出する。3,000以上なら残高をそのまま返す。毎分DBへ書き込む方式ではない。スロット精算は `balance - bet + total` で、自然回復上限による切り捨てはない。

孵化ゲージは強制バトルの保存と同じトランザクションで1増え、最大10。バトルを閉じて街に戻った後に中央から黄色い球を飛ばし、到着時にゲージ表示を進める。球は到着直後にremoveし、finallyでも除去する。10段階ならモジより優先して無料生成する。生成開始時にdraftへ `payment:'hatch'` を記録し、生成確定時にゲージを0にする。通常生成の課金はdraft予約時で、既存draftは再課金しない。

追加バトルはユーザー指定でゲージ+2（最大10）。既存の到着演出を2段階分再生する。残り1段階なら10までの1段階分のみ表示する。

卵の下には現在の生成コストを表示し、満タン時はグレーにする。生成途中は既存コードどおり「つづき」。ゲージは生成不可でも黄色、満タンは明るい黄色。

### 生成コスト・初期モジの変更

| 生存マイエモジン | 生成コスト |
|---|---:|
| 0体 | 100モジ |
| 1体 | 200モジ |
| 2体 | 400モジ |
| 3体 | 800モジ |
| 4体 | 1,000モジ |
| 5体以上 | 1,200モジ |

正本は `EmojinEngine.GENERATION_COSTS` と `generationCost`。自分が所有するstatus activeのエモジンを数え、死亡・レジェンド・NPC・他人は除く。休止・休眠は生死とは別なので、生存数から除外しない。表示と生成開始時の残高確認で同じ計算を使う。保存時はサーバーからactive一覧を取得し直して価格を決める。トランザクションでmetaも読み、生成・戦闘による変更時は再試行する。予約済みdraftは維持して再課金せず、孵化ゲージ10の無料生成を優先する。

初期モジの正本は `EmojinEngine.INITIAL_MOJI = 2000`。新規登録ではオーナーと初期walletを同じトランザクションで作り、古い未ログイン端末の3,500モジを新規アカウントへ取り込まない。既存Firestoreウォレットと既存アカウントの旧ローカルウォレット移行は維持する。

星バッジは共通の `.star-badge` により、黄色の星・黒文字へ統一。街・詳細・バトル・一覧・レジェンド表示に同じ配色を使う。

## 戦闘・休止・休眠・NPC

### 手動バトルの種類（追加仕様）

強制バトルの上の上向き三角から、上へ開くメニューを表示する。縦2行でチャレンジ（⚔️＋星）、マイエモジン（⚔️＋👤）の順。アイコンの右に200モジを表示し、既存ナビのアイコン寸法とコストの書体を共用する。メニュー外タップ・Escapeで閉じ、キーボードの上下/Home/Endでも選択できる。メニューを開いている間はPWAの自動再読み込みを待機する。

- `forced`：既存どおり参加可能な全体から異なる2体。100モジ・ゲージ+1。
- `challenge`：街の星マークと同じ最大星数のチャンピオンから1体、残りの参加可能エモジン全体から1体。同率はランダム、全員0星なら全員が候補。200モジ・ゲージ+2。
- `mine`：参加可能なマイエモジンから1体、残りの参加可能エモジン全体から1体。相手が別のマイエモジンや別のチャンピオンでもよい。200モジ・ゲージ+2。

休止・休眠は既存どおり抽選から除外する。街に表示中のチャンピオンが全員休止なら、低い星数の相手をチャンピオンに繰り上げず、チャレンジを無効化する。残高不足、対象不在、参加可能数2未満でも該当メニューを無効化する。開始直前に状態を再取得し、保存トランザクションでも費用・対象・所有者・チャンピオン資格・参加条件を再確認する。

定義の正本は `EmojinEngine.BATTLE_MODES`、抽選は `battleAnchors` / `selectBattlePair`。`battleRequest.mode` を未送信キューにも保持する。modeのない旧キューはforcedとして扱い、既存バトルIDが保存済みなら再課金・再加算しない。

変更範囲は手動の抽選・精算とUIであり、`battle`・`planBattle`・`hourly` の戦闘解決規則とGASの定期バトルには変更なし。GASに新しい手動バトルを追加する必要はない。

### 戦闘解決と参加条件

戦闘は `rulesVersion:3`。生成時HPは5〜10、通常5スロットは攻撃1:30、攻撃2:22、ハズレ:18、回復:10、防御:10、カウンター:10の重み。スペシャル候補は毒・強攻撃・吸血・体当たり・ツイン・全回復・呪いから2つ提示する。

イベントは毒ダメージと継続判定、出目・呪い解除・ツイン、回復、防御、攻撃/吸血/体当たり反動、反射、毒付与、呪い付与、終了の順。フェーズ内は共有スナップショットを基準に同時解決する。死亡はHP0、生存時は星+1、星50でレジェンド。特殊な組み合わせの詳細は `battle` を正本とし、変更時はGAS側との一致を確認する。

- 未確認バトル7件以上で休止し、抽選対象から除外する。
- `ownerPresence` の休眠条件は `!accessed && suspended && now - max(suspendedAt,lastAccessAt) >= 5日`。単純な未アクセス5日ではない。
- suspendedAt欠落時は現在時刻、lastAccessAt欠落時はcreatedAtまたは現在時刻を使う。初回の保守判定で即休眠にはしない。
- `touchAccess` はアクセスを記録し、休眠を解除する。通常は5分以内の重複更新を抑える。復帰時は「エモジンが再び／活動を始めた」と復活演出。未確認件数による休止解除は既読処理に依存する。
- `planBattle` は解決後の参加可能数が10未満ならNPCで補充する。休止・休眠オーナーは数からも除く。
- NPCはカタカナ3文字＋「ン」、オーナー名NPC、ownerUid npc、isNpc true。5通常スロットはランダム、6番目はattack1。
- NPCは墓地のクエリとUIから除外。レジェンド一覧では一律除外していない。
- `hourly` 関数は通常1戦後、active数が30以下になるまで追加戦闘する実装を持つが、ブラウザーからの定期呼び出しは確認できない。GASの定期処理が同じコードかは未確認。

## MOJI SPIN

確率・配当は `MojiSpinEngine.CONFIG` に集約し、還元率による自動調整は行わない。3×3の独立抽選、横3・縦3・斜め2の8ライン、1ライン1BET・合計8モジ固定。

| 絵柄 | 確率 | 1ライン配当 |
|---|---:|---:|
| 🤡 WILD | 3% | 400 |
| 😄 | 4% | 160 |
| 🎁 | 6% | 80 |
| 🔔 | 9% | 50 |
| 🍉 | 12% | 30 |
| 🫐 | 14% | 20 |
| 🍊 | 16% | 14 |
| 🍒 | 18% | 10 |
| ブランク | 18% | 0 |

3つ揃いで当選。WILDは配当対象の代替となり、1ラインは成立する最大配当のみ、複数ラインは合算する。同じWILDを別ラインで別の絵柄として扱える。WILD3つは400、ブランクを含むラインは不成立。

通常スピンの中央がWILDなら必ずフリー突入。回数は一度だけ抽選：4回40%、5回30%、7回20%、10回8%、20回2%。フリーは中央WILD固定、他8マスは通常確率、配当も同じ、BET不要、再突入・追加回数なし。通常スピン分の配当もTOTALへ含める。

`createRound` はSPIN時に通常・回数・全フリー結果を生成する。`validateRound` が構成と配当整合性を検証する。`spinSlot` はキューに同じroundとIDを保持し、FirestoreトランザクションでBETと全配当を先に精算する。receipt・slotRoundで重複や別端末の進行中結果を扱う。保存直後の結果はトランザクションの戻り値を使い、余分な残高再取得で次の結果と混同しない。

表示側の `session.balance` はFirestoreの最終残高と分離する。

1. クリック時に8を引いた演出残高を表示して回転。保存結果が来るまで停止しない。
2. 回転開始から最低1秒後、`[0,1,2,5,8,7,6,3,4]` の順に0.1秒間隔で停止。中央は最後。
3. 全停止の0.5秒後に当選ラインを表示。線は最初と最後のマスの端まで延ばす。
4. フリー突入時は中央WILDを1秒強調し、ルーレットのタップ待ち。タップ後3秒回転、停止0.5秒後に決定数を大きく表示する。
5. ルーレット消去後も数字を残し、縮小して中央WILD右下の残数表示へ移動する。
6. フリーは自動進行し、停止時に残数を1減らす。当選ライン表示から1秒で次へ。上部の「1/4」等は表示しない。
7. 全フリー後TOTAL WINを表示し、タップで閉じる。その後に合計配当を演出残高へ反映する。
8. `finishSlot` が保存上の進行中ラウンドを解放してから次回SPINを許可する。

中断結果はモーダルを開いた時の `getSlotRound` で検出し、自動復帰する。通常の次回SPINのクリックで前回結果を再生しない。エラー時は失敗状態で操作を止め、開き直して復帰する。

UIは丸い金色🎰ボタン、絵文字37.5px、SkranjiのMOJI SPIN見出し、Aldrichの英数字、左下BET/WIN・右下保有モジ。3行は均等。操作はSPINのみ、残高8未満や回転・保存・演出中は無効。タイトル下の状況文字はDOMのhiddenと `.spin-phase{display:none!important}` で常時非表示。

配当表は反映済み。`showSlotOdds` が別のネイティブdialogを開き、配当対象8絵柄と倍率をCONFIGから生成する。WILD表記、中央WILDの3×3図、Free Spin説明を備える。回転・読み込み中は開けない。閉じても元のスロットモーダルは維持する。

## PWA更新の確認

`sw.js` は `index.html`・`app.js`・`style.css` の全文をまとめてSHA-256化する。新シェルを先にキャッシュへ準備し、`CHECK_SHELL` と `APPLY_SHELL` メッセージで選択を切り替える。HTMLが参照するJS/CSSにはシェル名のクエリを付ける。

`index.html` は読み込み・再表示・オンライン復帰・5分間隔に更新を確認し、1秒間隔で適用可能か見る。`EmojinCanReload` はbusy・戦闘・モーダル・入力中・生成途中・未送信操作・復帰/孵化/落とし物演出等を確認する。`EmojinPrepareReload` でbusyを立ててからシェル適用とページ置換を行う。

注意：SW自身の更新ではinstall中にskipWaiting、activateでactiveシェル切替・旧キャッシュ削除・clients.claimを実行する。この経路はアプリ側の適用可否判定を通らない。即座にページを強制再読み込みするコードではないが、プレイ中のキャッシュ切替・複数タブへの影響まで安全と断定できない。今回は変更せず、SW変更時の追加検証事項とする。

画像・manifestは既存activeキャッシュを優先して再利用し、コア3ファイルのハッシュにも含めない。画像だけの更新はこのシェル検知の対象外。Firebase SDKは別キャッシュ。オフラインの静的表示が可能でも、認証やFirestoreのゲーム操作まで完全オフライン対応とは扱わない。
