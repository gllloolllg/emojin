# 吸血・体当たりの調整（2026-11-16）

実装・検証済み。2026-11-16、ユーザーから稼働GASのEngine.gs差し替え保存完了の報告を受領した。フロントを公開し、配信一致を確認した後、ユーザーがfinishV4Migrationを実行して停止を解除する。稼働GASへの直接接続は未設定。

## 効果

- 全モードで吸血は1ダメージ・最大1回復。防御・カウンターを受けない。敵の残りHPがない場合は奪えず、元から満タンなら回復超過は切り捨てる。
- ミニゲームでは吸血による回復は元の最大HP（baseMaxHp）まで。既に回復済みの金色HPを減らさず、同時攻撃で減った分を考慮して回復する。通常の回復アイテム・回復能力が金色枠を埋める処理は維持する。
- 体当たりは攻撃4・通常時の反動2を維持。有効なカウンターに反射された場合だけ反動2を免除し、通常の単発反射なら使用者は4ダメージだけ受ける。
- 呪いでカウンターが無効だった場合は反動2が残る。ツインでカウンター2個なら反射8、別攻撃が同時に出た場合の追加ダメージ、毒などは従来どおり。ターン全体の被ダメージを4で制限する変更ではない。
- プレイヤー・敵・中ボス・ラスボスに同じ計算を適用。😈の専用抽選・超必殺技・n・抽選確率は変更しない。

## 説明文

FACESの説明と生成時のshortFaceTextを更新。吸血には「防御やカウンターの影響をうけない」を明記し、回復上限と体当たりの反射時の反動免除も説明する。

## 変更ファイルと互換性

- app.jsが通常の能力計算の正本。scripts/sync-gas-engine.cjsでgas/Engine.gsへ完全同期する。
- adventure/engine.jsにも同じ変更を適用し、追加のbaseMaxHp回復上限だけを持たせる。
- 既存のrulesVersion 4、成績・💀・モジ・孵化・ランキング・保存構造は維持する。個体のslotsは能力IDなので、保存済み個体の一括書き換えは不要。
- 過去のログは保存済みイベントとHP・報酬を再生し、再計算・書き換えをしない。旧版の検証用fixtureも書き換えず、旧能力一致テストは今回変更する2能力を対象外にし、専用の新テストで検証する。
- Firestoreルール・Code.gs・Migration.gs・トリガー設定の変更は不要。

## 本番への反映手順

GASはこの環境から直接操作できず、clasp認証・Apps Script管理者接続もない。以下の管理画面操作だけをユーザーが行う。フロントはその保存確認後にこちらで公開する。

1. Apps Scriptの現在のEngine.gsを控え、既存のpauseForV4Migrationを実行する。この関数はmaintenance=trueにするだけで、個体の移行や成績のリセットを行わない。既存の定期トリガーは停止フラグを読んで待機するので、削除・追加はしない。
2. このブランチのgas/Engine.gsを、同じGASプロジェクトのEngine.gsへ全文貼り替えて保存する。Code.gs・Migration.gs・接続先・Firestoreルールは変更しない。migrateToV4は実行しない。
3. 保存完了をこのチャットで知らせる。こちらでmainへマージ・GitHub Pages公開・配信ファイル一致を確認する。
4. 公開完了後、既存のfinishV4Migrationを実行してmaintenanceを解除する。この関数の読み取り検査と停止解除だけを使い、移行関数は実行しない。アプリを閉じて開き直して更新する。

GitHub Pagesへのマージだけでは、稼働中のGASは更新されない。
