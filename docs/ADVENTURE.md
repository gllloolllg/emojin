# エモジンのぼうけん

## 組み込み
- 街右側の丸ボタンは上から🗡️、🎰、🔢。🗡️で同一オリジンの全画面iframeを開く。既存画面のCSSとDOMを隔離し、「おわる」で街へ戻る。
- タイトル右下に `1PLAY 100モジ`。所持100未満または生存マイエモジンなしでは開始不可。タイトル・説明・ランキングは無料。
- 「はじめる」で既存の共通操作キューから `adventureStart` を実行し、walletと不変receiptを同一トランザクションで保存。失敗時は同じ操作IDを再送し二重課金を防ぐ。リトライ中は他のタイトル操作を無効化。
- 生存中の本人個体（NPC除外、休止/休眠とは独立）から均等に抽選。保存トランザクションでも所有・生存・残高を再確認する。HP満タンでコピーし、以降は主ゲーム個体を変更しない。
- 全プレイヤーのstatus=legendを件数制限なしで取得し均等抽選。開始receiptに名前・絵文字・6能力のスナップショットを保持し、地下10階生成に使用。HP40固定。レジェンドなしの場合のみ中ボス抽選の能力を持つHP40の敵。
- 終了/途中退場/リロードの返金・中断復帰はなし。保存済み開始receiptの再試行は同じ抽選個体を返す。

## ファイル
- `adventure/` は最終試遊版（2026-11-13 / standalone 0461d1c）を基礎に、本番用HOSTアダプターを接続した静的画面。
- `adventure-store.js` は開始・スコアの共通ウォレット処理。`createCloud` の既存writeOperationから呼ぶ。
- `adventure/engine.js` は最新のapp.js純エンジンと同一、ただし全回復だけ `baseMaxHp` を上限にし、有効化済みの金ハートを減らさない。通常メイン/GASのエンジンは変更しない。
- PWAのCOREに全ファイルを含め、キャッシュ名前空間を分ける。iframeを開いている間はEmojinCanReload=false。

## スコア v3
- ザコ撃破：最大HP×400。爆弾取得：個数×100。回復ハート：100。宝箱開封：300。宝箱全回復：300。開封と中身は両方加算。
- 中ボス撃破：1000。階層移動：移動先×500。レベルアップ：到達レベル×1000。
- 遭遇時：ザコLv×300（ランダム）、×500（マップ）。撃破しなくても加算。
- ラスボスのハート位置×100：爆弾・通常共通。40→39は100、35→34は600、回復して36→35は500。複数個は各位置を合計。超過は加点なし。
- 固定クリア・ラスボス撃破・探索ボーナスはなし。

## 保存とランキング
- 共通walletの `adventureScoresV3` 配列に個人上位10件のみ保存。
- `adventureScoresV3/{uid}` は各人の上位10プレイも保存。最高得点の上位10人から記録を集め、全プレイとして並べ替えた上位10件を全員ランキングに表示。同じプレイヤーが複数の順位に載る。名前はFirestore ownersのプレイヤー名で、HTMLをエスケープ。
- 終了時に `adventure-<UUID>-result` の不変receiptとwallet個人10件、共有の個人上位10件もを同一トランザクションで保存。同点ではベスト更新しない。
- 終了結果の未送信操作は既存キューに残し、再送する。結果画面でも再試行可能。保存前にタイトルへ進ませない。
- スコア集計は配点イベントと一致することを検証し、共有ベストのルールでも本人・支払receipt・プレイヤー名・結果receipt・得点一致を確認する。
- 既存ゲーム同様にクライアントがゲーム結果を計算する信頼モデル。サーバーによる全行動再現/改ざん耐性は実装していない。試遊版の「サーバー検証」は将来案で、今回の実装と区別する。身内以外に公開して強い不正対策が必要な場合は別途サーバーの権威的実行が必要。
- 全プレイの詳細ログは保存しないが、料金/結果のreceiptは二重実行防止のため残す。スコア世代3のみ比較。旧試遊のブラウザ記録は移行しない。

## 経験値と固定マスの更新
- ザコ撃破の経験値はザコLvと同じ（地下1〜3階で1、4〜7階で2、8〜10階で3）。逃走時は0、中ボス撃破は3、ラスボスは0のまま。
- レベルごとの必要経験値、レベルアップ時の最大HP増加・その場で回復しない処理、配点式は維持する。
- ダンジョンとあそびかた2ページの5×5グリッドは全行・全列を均等な固定トラックにし、内容の固有サイズで広がらないようサイズ計算を隔離する。大きな絵文字は重ねて描画するが、マスの大きさには影響させない。


## 全員ランキングの複数記録対応
- 各ユーザーの公開ドキュメントにentries（個人上位10件）をミラーし、プレイ終了時にwallet・結果receiptと同時更新。
- 最高点が上位10人のドキュメントだけを取得しても、全プレイの上位10件を求められる。それ以外の人の最高点は少なくとも10人の最高点以下なので、全体上位10件には入らない。
- 配点と記録世代は変更しない。既存共有ドキュメントにentriesがない場合は従来の最高1件を表示。本人が次のプレイを完了すると、既存walletにある個人10記録を自動で共有へ反映する。別途のデータ移行はしない。
- ルールは旧クライアントの最高点保存も許可したまま新形式を追加。新フロントの公開前にルール全文を適用する。

- 同点の全体順位はユーザーID順（Firestoreの得点降順クエリの暗黙ドキュメントID順）で決め、その人の同点記録は達成時刻順とする。これにより最高点上位10人の取得で同点を含む全体10件を選べる。
