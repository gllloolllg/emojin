# エモジン：GitHub Pages ＋ スプレッドシート ＋ GAS

画面は GitHub Pages、住人・生成途中の内容・バトル履歴は Google スプレッドシートに保存します。モジは **端末のブラウザの localStorage のみ**に保存します。Firebase は使いません。

## 仕組み

- 初回登録後に 3000 モジ。表示・回復（1 分に 1 モジ、上限 3000）・生成時 1400 モジ／強制バトル時 100 モジの消費はフロントエンドだけで計算します。GAS は残高を見ません。
- GAS はプレイヤー名の重複防止、生成内容の保管、バトルの抽選・確定、記録、毎時の自動実行を担当します。スクリプトロックで同時更新を順番に処理します。
- 一人の端末は、初回に生成したランダムな端末トークンで識別します。サーバーに保存するのはトークンのハッシュだけです。名前の入力後、初回ヒントを4つ表示します。
- 街は画面を開いている間 **60 秒間隔**で更新します。タブを戻したときにも取得します。GAS の時間トリガーは毎正時に固定できないため「約1時間ごと」です。サーバーで発生したバトルが見えるまで、トリガーの遅れ＋最大約1分（画面を閉じている間は再訪時まで）の遅延があります。
- GitHub Pages から別ドメインの GAS に呼び出すため、書き込みは本文にトークンを載せる `text/plain` POST、結果の確認は使い捨てIDによる読み取り専用 JSONP です。トークンを JSONP のURLに付けません。シートの共有権限はプレイヤーに渡さないでください。

## 1. スプレッドシートと GAS を作る

1. 空のスプレッドシートを一つ作成します。このシートは公開・共有せず、管理者だけが編集できるようにします。
2. 「拡張機能 → Apps Script」を開き、既存の `コード.gs` の内容を `gas/Code.gs` で置き換え、さらに `gas/Engine.gs` を新規スクリプトファイルとして追加します。2ファイルとも **先頭から末尾まで**貼り付けます。
3. エディタ上部の関数選択から `setupEmojin` を選んで一度実行し、権限を承認します。`players`、`emojins`、`battles`、`legends`、`meta` の各シートと、1時間おきのトリガーが作成されます。`setupEmojin` をもう一度実行しても、トリガーは重複しません。
4. 「デプロイ → 新しいデプロイ → ウェブアプリ」を選び、**実行ユーザー＝自分、アクセスできるユーザー＝全員**としてデプロイします。URL末尾が `/exec` のものを控えます。コードを変更したときは「デプロイを管理 → 編集 → 新バージョン」で更新します。

## 2. GitHub Pages を設定する

1. このフォルダーの中身を、`.github` フォルダーを含めて GitHub リポジトリのルートへ置き、`main` ブランチに push します。`node_modules`、`dist`、`.env` は置きません。
2. GitHub リポジトリの **Settings → Secrets and variables → Actions → Variables** に、`VITE_GAS_URL` という名前で先ほどの `/exec` URL を登録します。
3. **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。同梱の `.github/workflows/pages.yml` がテスト・ビルド・公開を行います。通常の `ユーザー名.github.io/リポジトリ名/` ではパスが自動設定されます。独自ドメインの場合は GitHub 変数 `PAGES_BASE_PATH` に `/` を設定します。

## ローカルで確認する

Node.js と npm が必要です。`.env.example` を `.env` にコピーして `/exec` URL を入力します。

```sh
npm ci
npm test
npm run dev
```

`npm test` はバトルルール28件と、スプレッドシート/GAS の模擬実行テストです。**公開後の GAS Web アプリへの実通信**は、プレイヤー登録・生成・バトルで別途確認してください。`doPost` の結果は一時的なキャッシュを介して確認するため、ネットワーク障害中は再読み込みして結果を確認してください。

## 仕様上の限界

- モジの計算は端末の時計と保存領域に依存します。時計変更・データ削除・ブラウザ変更で残高を正しく引き継げず、利用者が操作すればモジを増やせます。GAS はモジ不足を検証しません。公平性が必要な公開ゲームには使えません。
- 端末トークンの保存領域を消すと、元のプレイヤーやエモジンに戻れません。シートのプレイヤー情報を直接消さないでください。
- スプレッドシートの更新はデータベースのトランザクションではありません。途中で GAS が停止すると、住人・バトルログの一部が先に更新される可能性があります。大人数での同時利用を想定していません。
- GAS には同時実行数・処理時間などの無料利用枠があります。毎日多数のユーザーが長時間開きっぱなしにする場合は、利用状況を確認してください。
- 墓地や履歴が非常に大きくなると、GAS の一時キャッシュ（1件100 KB）に収まらず、読み込みに失敗します。長期・大規模運用の際は履歴のページ分けが必要です。
